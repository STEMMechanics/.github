# Contributing to STEMMechanics

Thanks for wanting to help! STEMMechanics projects are built for learning,
creating and sharing. You do not need to be an expert to contribute. Young
people, first-time coders, teachers, families and experienced developers are
all welcome.

You can help by:

- reporting something that does not work;
- suggesting a clearer explanation or a new idea;
- improving code, tests, artwork or documentation; or
- politely reviewing and testing somebody else's work.

## Before you start

1. Read the repository's `README` to learn what the project does.
2. Search the issues to see whether somebody has already raised the same idea.
3. For a large change, open an issue before spending lots of time on it.
4. Never post passwords, access tokens, private addresses, phone numbers or
   other personal information.

If you are under 18, ask a parent, carer, teacher or another trusted adult for
help before sharing personal information or communicating privately with
someone you do not know. Project conversations should stay in public GitHub
issues and pull requests whenever possible.

## Reporting a problem

Open an issue and tell us:

- what you were trying to do;
- what you expected to happen;
- what happened instead; and
- the steps we can follow to see the problem.

Screenshots and logs can help, but check them first and remove private
information. Security problems should be reported privately by following
[`SECURITY.md`](SECURITY.md).

## Sending a change

A **pull request** is a request to add your changes to a project.

1. Create a fork or branch.
2. Make one focused change and explain why it is useful.
3. Test it using the instructions in that repository.
4. Open a pull request and complete the checklist.
5. Be ready to answer friendly questions or make small improvements.

It is okay if your first attempt is not perfect. Reviews are part of building
software together, not a test of whether you belong here.

## Working together

Be kind, patient and specific. Discuss the work, never attack the person. By
participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

Maintainers may close work that is unsafe, outside the project's goals,
inactive for a long time or not something the team can support. We will try to
explain why.
